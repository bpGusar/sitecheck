# sitecheck

Веб-страница, которая проверяет, открывается ли сайт из вашей сети, и показывает, что именно не открывается. Работает на Windows 11, macOS и Linux.

Что делает одна проверка:

1. Открывает сайт в headless Chromium (Playwright) и собирает все домены, к которым обращается страница.
2. Резолвит каждый домен через 9 DNS: системный, UDP 1.1.1.1 / 8.8.8.8 / 77.88.8.8 и DoH Cloudflare / Google / Quad9 / AdGuard / Яндекс. IP-адреса объединяются без дублей.
3. К каждому IP пробует TCP, TLS с SNI и HTTP GET. GET нужен, чтобы поймать блокировку «заморозкой», когда соединение молча обрывается после ~16 КБ.
4. Определяет ASN каждого IP по 6 источникам: iptoasn, ip-location-db, Team Cymru, RIPEstat, ip-api, ipinfo.
5. Помечает рекламу и трекеры по спискам AdGuard DNS filter и Disconnect.
6. Собирает блок «Что добавить в прокси/VPN»: домены, IP «добавлять» и IP «под вопросом» (ротация, общий CDN, CloudFront, IP только от одного DNS).

Проверка идёт из сети того компьютера, где запущен sitecheck, и через его VPN, если он включён. История последних 50 проверок хранится в папке `data`.

## Установка и запуск

Нужно около 1 ГБ на диске: Chromium ~300 МБ, базы ASN ~500 МБ. Первый запуск сам ставит всё нужное и идёт 2–10 минут, следующие — несколько секунд.

### Windows 11

**1. Установить Python.**

1. Откройте https://www.python.org/downloads/ и нажмите жёлтую кнопку **Download Python 3.x.x**.
2. Запустите скачанный файл.
3. **Внизу первого окна поставьте галочку «Add python.exe to PATH»**, затем нажмите **Install Now**.
4. Дождитесь «Setup was successful» и нажмите **Close**.

**2. Скачать sitecheck.**

1. Откройте https://github.com/bpGusar/sitecheck.
2. Зелёная кнопка **Code** → **Download ZIP**.
3. Откройте папку «Загрузки», нажмите правой кнопкой на `sitecheck-main.zip` → **Извлечь все…** → **Извлечь**.

Получится папка `sitecheck-main`, внутри неё файлы `start.bat`, `README.md` и папка `app`.

**3. Запустить.** Дважды щёлкните `start.bat`.

- Если Windows покажет предупреждение безопасности — нажмите **Запустить**. Если это синее окно «Windows защитила ваш компьютер» — **Подробнее** → **Выполнить в любом случае**.
- Откроется чёрное окно. В первый раз в нём долго идёт установка — это нормально.
- Когда появится строка `Uvicorn running on http://127.0.0.1:8090`, откройте в браузере **http://localhost:8090**.

**Остановить:** закройте чёрное окно (или нажмите в нём `Ctrl+C`). Пока окно открыто, страница работает.

### macOS

**1. Установить Python.**

1. Откройте https://www.python.org/downloads/ и нажмите жёлтую кнопку **Download Python 3.x.x**.
2. Откройте скачанный `.pkg` и пройдите установку кнопками **Продолжить** → **Установить** (попросит пароль от Mac).

Встроенный в macOS `python3` часто слишком старый (нужен 3.10 или новее), поэтому ставим с python.org.

**2. Скачать sitecheck.**

1. Откройте https://github.com/bpGusar/sitecheck.
2. Зелёная кнопка **Code** → **Download ZIP**.
3. В «Загрузках» дважды щёлкните `sitecheck-main.zip` — появится папка `sitecheck-main`.

**3. Запустить.**

1. Откройте **Терминал**: `Cmd+Пробел`, наберите «Терминал», `Enter`.
2. Вставьте и нажмите `Enter`:

   ```bash
   cd ~/Downloads/sitecheck-main && bash start.sh
   ```

3. Если macOS спросит «Терминал запрашивает доступ к файлам в папке „Загрузки“» — нажмите **Разрешить**.
4. Когда появится строка `Uvicorn running on http://127.0.0.1:8090`, откройте в браузере **http://localhost:8090**.

**Остановить:** в окне Терминала нажмите `Ctrl+C`.

### Linux

Нужны Python 3.10+ с модулем venv и git. Для Ubuntu/Debian:

```bash
sudo apt install python3 python3-venv git
git clone https://github.com/bpGusar/sitecheck.git
cd sitecheck
bash start.sh
```

Если Chromium не запускается из-за недостающих системных библиотек (в логе `Host system is missing dependencies`), один раз выполните:

```bash
sudo .venv/bin/python -m playwright install-deps chromium
```

Страница — **http://localhost:8090**, остановить — `Ctrl+C`. Для сервера, где sitecheck должен работать постоянно, удобнее [Docker](#docker-linux-сервер).

## Настройки

Все настройки — в файле `settings.env` в папке sitecheck. Без него работают значения по умолчанию.

**Создать файл:** скопируйте `settings.env.example` в `settings.env` и откройте его в текстовом редакторе.

- Windows: правой кнопкой на `settings.env.example` → **Копировать**, затем **Вставить** в той же папке и переименуйте копию в `settings.env`. Открыть — правой кнопкой → **Открыть с помощью** → **Блокнот**. Если расширения файлов не видны: в Проводнике **Вид** → **Показать** → **Расширения имён файлов**.
- macOS / Linux: `cp settings.env.example settings.env`, затем `nano settings.env` (сохранить `Ctrl+O`, `Enter`, выйти `Ctrl+X`).

После правки перезапустите sitecheck: остановите и запустите снова.

| Настройка       | По умолчанию | Что это                                                                                     |
|-----------------|--------------|---------------------------------------------------------------------------------------------|
| `HOST`          | `127.0.0.1`  | `127.0.0.1` — страница открывается только на этом компьютере; `0.0.0.0` — и с других устройств |
| `PORT`          | `8090`       | порт страницы                                                                               |
| `AUTH`          | `none`       | вход: `none`, `basic` или `authentik` — см. [Вход на страницу](#вход-на-страницу)           |
| `AUTH_USER`     | —            | логин для `AUTH=basic`                                                                      |
| `AUTH_PASSWORD` | —            | пароль для `AUTH=basic`                                                                     |
| `DATA_DIR`      | папка `data` рядом с приложением | где хранить базы и историю                                              |

Те же настройки можно задать переменными окружения — они важнее файла.

Проверки идут строго по одной (Chromium тяжёлый); одна проверка прерывается через 10 минут, чтобы не стопорить очередь.

## Вход на страницу

### Без пароля

`AUTH=none` — по умолчанию. Подходит, пока `HOST=127.0.0.1`: страница открывается только на этом же компьютере.

### Логин и пароль (basic)

В `settings.env`:

```ini
AUTH=basic
AUTH_USER=admin
AUTH_PASSWORD=придумайте-длинный-пароль
```

При открытии страницы браузер покажет окно входа. Браузер запоминает вход до закрытия, кнопки «Выйти» в этом режиме нет.

Пароль передаётся открытым текстом, если страница открыта по `http://`. Для домашней сети это приемлемо; для доступа из интернета ставьте перед sitecheck reverse proxy с HTTPS (Caddy, nginx).

### authentik

Режим для случая, когда перед sitecheck стоит reverse proxy с forward auth от [authentik](https://goauthentik.io). Сам sitecheck пароль не проверяет — это делает authentik, а страница показывает, кто вошёл, и кнопку **«Выйти»**.

В `settings.env`:

```ini
HOST=127.0.0.1
AUTH=authentik
```

`HOST` обязательно `127.0.0.1`: иначе в sitecheck можно зайти напрямую, мимо authentik.

Дальше нужно два шага: приложение в authentik и сайт в reverse proxy. Ниже — для Caddy; authentik и Caddy должны быть уже установлены, домен `sitecheck.<ваш-домен>` должен указывать на этот сервер.

**1. Приложение в authentik.**

1. Откройте authentik → **Admin interface**.
2. Слева **Applications → Applications** → кнопка **Create with Provider**.
3. Шаг **Application**: Name `Sitecheck`, Slug `sitecheck` → **Next**.
4. Шаг **Choose a Provider**: **Proxy Provider** → **Next**.
5. Шаг **Configure Provider**:
   - Authorization flow: `default-provider-authorization-implicit-consent`;
   - сверху выберите режим **Forward auth (single application)**;
   - External host: `https://sitecheck.<ваш-домен>`;
   - **Next**.
6. Шаг **Configure Bindings**: можно пропустить → **Next** → **Submit**.
7. Слева **Applications → Outposts** → у **authentik Embedded Outpost** нажмите карандаш (**Edit**) → в списке **Applications** перенесите `Sitecheck` направо → **Update**.

Без шага 7 вход будет зацикливаться или отдавать 404.

**2. Сайт в Caddy.** `9000` — порт authentik, `8090` — порт sitecheck:

```caddyfile
sitecheck.<ваш-домен> {
	route {
		reverse_proxy /outpost.goauthentik.io/* 127.0.0.1:9000
		forward_auth 127.0.0.1:9000 {
			uri /outpost.goauthentik.io/auth/caddy
			copy_headers X-Authentik-Username X-Authentik-Name
			trusted_proxies private_ranges
		}
		reverse_proxy 127.0.0.1:8090
	}
}
```

`route` обязателен: без него Caddy выполнит проверку входа раньше, чем пропустит `/outpost.goauthentik.io/*`, и возврат после входа уйдёт в бесконечный цикл. Применить: `caddy reload` (или `docker exec caddy caddy reload --config /etc/caddy/Caddyfile`, если Caddy в Docker).

**3. Проверить.** Откройте `https://sitecheck.<ваш-домен>` — должна появиться страница входа authentik, после входа — sitecheck с вашим именем и кнопкой «Выйти».

**Доступ другим людям.** Администраторам authentik приложение доступно сразу. Остальным: **Applications → Applications** → **Sitecheck** → вкладка **Policy / Group / User Bindings** → **Bind existing Policy / Group / User** → тип **User** или **Group** → выбрать → **Create**. Кнопка **Check access** там же показывает, пустит ли конкретного пользователя.

Выход из sitecheck не выходит из самого authentik: пока жив вход в authentik, повторный вход пройдёт без пароля.

Для nginx, Traefik и других прокси настройка forward auth описана в документации authentik: раздел *Providers → Proxy → Forward auth*. sitecheck нужны от прокси заголовки `X-Authentik-Username` и `X-Authentik-Name`.

## Открыть с других устройств

Чтобы открыть страницу с телефона или другого компьютера в той же сети:

1. В `settings.env`: `HOST=0.0.0.0` и `AUTH=basic` с логином и паролем.
2. Перезапустите sitecheck.
3. Узнайте адрес компьютера в сети:
   - Windows: **Параметры** → **Сеть и Интернет** → **Свойства** (у Wi-Fi или Ethernet) → строка **IPv4-адрес**;
   - macOS: **Системные настройки** → **Сеть** → **Wi-Fi** (или Ethernet) → **Подробнее** → **TCP/IP** → **IP-адрес**;
   - Linux: `hostname -I`.
4. На другом устройстве откройте `http://<этот-адрес>:8090`.

На Windows при первом запуске с `HOST=0.0.0.0` появится окно брандмауэра — отметьте **Частные сети** и нажмите **Разрешить доступ**.

## Обновление

- Скачано ZIP-архивом: скачайте новый ZIP и перенесите в новую папку свои `settings.env` и `data` (историю и базы, необязательно).
- Скачано через git: в папке sitecheck выполните `git pull`.

Затем запустите как обычно: `start.bat` / `start.sh` сами доставят изменившиеся зависимости.

Для разработчиков: версия `playwright` в `requirements.txt` должна совпадать с тегом образа в `Dockerfile`.

## Docker (Linux-сервер)

Для сервера, где sitecheck работает постоянно. Нужен Docker с плагином Compose. Docker на Windows и macOS не подходит: там контейнер работает в виртуальной машине, и проверка идёт не из сети компьютера.

```bash
git clone https://github.com/bpGusar/sitecheck.git
cd sitecheck
mkdir -p data
cp settings.env.example settings.env
docker compose up -d --build
```

- `mkdir -p data` — заранее, иначе Docker создаст папку от `root`, и приложение не сможет в неё писать.
- Контейнер работает от пользователя `1000:1000`. Если `id -u` у вас выводит другое число, поменяйте `user:` в `docker-compose.yml`.
- `network_mode: host` — проверка идёт ровно из сети сервера; `HOST` и `PORT` из `settings.env` действуют как обычно.
- Обновление: `git pull && docker compose up -d --build`. Логи: `docker compose logs -f`.
- Свои добавки к `docker-compose.yml` (метки, часовой пояс `TZ`) кладите в `docker-compose.override.yml` — Compose подхватит его сам, а git его не отслеживает.

## Данные

Всё лежит в папке `data` (или в `DATA_DIR`) и в git не попадает.

| Путь                                          | Что это                                       |
|-----------------------------------------------|-----------------------------------------------|
| `results/*.json`                              | история проверок, хранятся последние 50       |
| `ip2asn-combined.tsv.gz`                      | база ASN iptoasn.com                          |
| `asn-ipv4.csv`, `asn-ipv6.csv`                | база ASN ip-location-db                       |
| `adguard-dns-filter.txt`, `disconnect-*.json` | списки рекламы и трекеров                     |
| `aws-ip-ranges.json`                          | диапазоны AWS, чтобы узнавать CloudFront      |

Базы скачиваются при первом запуске и обновляются сами раз в сутки. Любой файл, кроме `results/`, можно удалить — он скачается заново. Удалить историю — удалить файлы в `results` и перезапустить sitecheck.

## Если что-то не так

**Окно `start.bat` сразу закрывается или пишет «Не найден Python».** Python не установлен или при установке не отмечена галочка «Add python.exe to PATH». Переустановите Python с этой галочкой, удалите папку `.venv` в папке sitecheck и запустите снова.

**«Нужен Python 3.10 или новее».** Установите свежий Python с python.org, удалите папку `.venv` и запустите снова.

**Установка упала на `pip install` или `playwright install`.** Обычно это сеть: проверьте интернет и запустите ещё раз — скрипт продолжит установку.

**`address already in use` / порт занят.** Порт 8090 занят другой программой. Поставьте в `settings.env` другой, например `PORT=8091`.

**Проверка висит «В очереди…».** Идёт другая проверка; они выполняются по одной. Зависшая проверка прерывается сама через 10 минут.

**Источник ASN пишет «база ещё скачивается».** Нормально в первые минуты после первого запуска. Если сеть медленно качает с Cloudflare, база iptoasn может качаться долго; остальные источники работают и без неё.

**Системный DNS отдаёт адреса `198.18.x.x`.** Это не ошибка sitecheck: на компьютере или роутере работает VPN/прокси-клиент с fake-IP. Такие адреса помечаются как fake-IP: трафик на них уходит в туннель, а не напрямую к сайту.

**UDP 8.8.8.8 возвращает странный адрес.** Провайдер может перехватывать UDP-запросы к публичным DNS и подменять ответ своей заглушкой. Для этого в проверке есть DoH — его так не подменить.

**authentik: бесконечный цикл входа или 404 на `/outpost.goauthentik.io/…`.** Приложение не добавлено в **authentik Embedded Outpost** (шаг 7) или в настройке Caddy нет `route`.

**authentik: «Request has been denied» после входа.** У пользователя нет привязки к приложению Sitecheck — см. «Доступ другим людям» в разделе [authentik](#authentik).

**Windows: «Windows защитила ваш компьютер».** Нажмите **Подробнее** → **Выполнить в любом случае**: `start.bat` не подписан, поэтому SmartScreen его не знает.
